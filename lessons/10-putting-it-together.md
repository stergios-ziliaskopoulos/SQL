# Μάθημα 10 — Πώς λύνεις ένα σύνθετο ερώτημα

## Στόχος

Να έχεις μέθοδο όταν η ερώτηση δεν χωράει σε ένα `SELECT`.

---

## 10.1 Η μέθοδος των πέντε ερωτήσεων

Πριν γράψεις γραμμή, απάντησε:

1. **Ποια είναι η μονάδα του αποτελέσματος;** Μία γραμμή ανά τι — πελάτη, βιβλίο, μήνα;
   Αυτό ορίζει το `GROUP BY`.
2. **Ποιοι πίνακες κρατούν τα δεδομένα;** Αυτό ορίζει τα `JOIN`.
3. **Ποιες γραμμές αποκλείω;** Αυτό ορίζει το `WHERE`.
4. **Τι υπολογίζω;** Αυτό ορίζει το `SELECT` και τις συγκεντρωτικές συναρτήσεις.
5. **Θέλω να δω και τα «μηδενικά»;** Αν ναι, `LEFT JOIN` αντί για `JOIN`.

Και μετά, χτίσε **σταδιακά**: γράψε το εσωτερικό κομμάτι, τρέξ' το, δες ότι βγάζει νόημα,
και μόνο τότε τύλιξέ το. Το «γράφω 60 γραμμές και μετά ψάχνω γιατί βγάζει λάθος» δεν δουλεύει.

## 10.2 Παράδειγμα: ένα πλήρες dashboard πελατών

**Ερώτηση:** για κάθε πελάτη, θέλω πόσα ξόδεψε συνολικά, πόσες παραγγελίες έκανε, ποια
ήταν η τελευταία, ποια κατηγορία αγοράζει περισσότερο, και σε ποια δεκάδα τζίρου βρίσκεται.

### Βήμα 1 — τα σύνολα ανά παραγγελία

```sql
SELECT o.id, o.customer_id, o.order_date,
       SUM(i.quantity * i.unit_price) AS σύνολο
FROM orders o
JOIN order_items i ON i.order_id = o.id
WHERE o.status = 'paid'
GROUP BY o.id, o.customer_id, o.order_date;
```

### Βήμα 2 — τα σύνολα ανά πελάτη

Τυλίγουμε το βήμα 1 σε CTE και ομαδοποιούμε ξανά, ένα επίπεδο πιο πάνω.

### Βήμα 3 — η αγαπημένη κατηγορία

Χωριστό CTE με `ROW_NUMBER()` ανά πελάτη, κρατάμε τη σειρά 1.

### Το τελικό ερώτημα

```sql
WITH σύνολα_παραγγελιών AS (
    SELECT
        o.id          AS order_id,
        o.customer_id,
        o.order_date,
        SUM(i.quantity * i.unit_price) AS σύνολο
    FROM orders o
    JOIN order_items i ON i.order_id = o.id
    WHERE o.status = 'paid'
    GROUP BY o.id, o.customer_id, o.order_date
),
ανά_πελάτη AS (
    SELECT
        customer_id,
        COUNT(*)         AS παραγγελίες,
        SUM(σύνολο)      AS τζίρος,
        MAX(order_date)  AS τελευταία_αγορά
    FROM σύνολα_παραγγελιών
    GROUP BY customer_id
),
κατηγορίες_πελάτη AS (
    SELECT
        o.customer_id,
        c.name                         AS κατηγορία,
        SUM(i.quantity * i.unit_price) AS αξία,
        ROW_NUMBER() OVER (
            PARTITION BY o.customer_id
            ORDER BY SUM(i.quantity * i.unit_price) DESC
        ) AS σειρά
    FROM orders o
    JOIN order_items i ON i.order_id = o.id
    JOIN books       b ON b.id = i.book_id
    JOIN categories  c ON c.id = b.category_id
    WHERE o.status = 'paid'
    GROUP BY o.customer_id, c.name
)
SELECT
    cu.first_name || ' ' || cu.last_name AS πελάτης,
    COALESCE(cu.city, '(άγνωστη)')       AS πόλη,
    COALESCE(ap.παραγγελίες, 0)          AS παραγγελίες,
    ROUND(COALESCE(ap.τζίρος, 0), 2)     AS τζίρος,
    ap.τελευταία_αγορά,
    kp.κατηγορία                         AS αγαπημένη_κατηγορία,
    NTILE(4) OVER (ORDER BY COALESCE(ap.τζίρος, 0) DESC) AS τεταρτημόριο
FROM customers cu
LEFT JOIN ανά_πελάτη        ap ON ap.customer_id = cu.id
LEFT JOIN κατηγορίες_πελάτη kp ON kp.customer_id = cu.id AND kp.σειρά = 1
ORDER BY τζίρος DESC;
```

Πρόσεξε τρία πράγματα:

- Τα `LEFT JOIN` κρατούν τους πελάτες **χωρίς** παραγγελίες (Θανάσης, Δέσποινα) με μηδενικά.
- Η συνθήκη `kp.σειρά = 1` μπαίνει στο `ON`, όχι στο `WHERE` — αλλιώς θα έπεφταν έξω
  ακριβώς αυτοί οι πελάτες (Μάθημα 5).
- Το `NTILE(4)` μοιράζει τους πελάτες σε 4 ίσες ομάδες κατά τζίρο.

Τρέξ' το:

```
python3 sql.py -f examples/dashboard.sql
```

## 10.3 Πώς εντοπίζεις λάθος αποτέλεσμα

**Βγαίνουν περισσότερες γραμμές απ' όσες περίμενες;**
Κάποιο `JOIN` πολλαπλασιάζει. Τρέξε `SELECT COUNT(*)` πριν και μετά από κάθε `JOIN` και βρες ποιο.

**Βγαίνουν λιγότερες;**
Κάποιο `INNER JOIN` έπρεπε να είναι `LEFT`, ή μια συνθήκη `WHERE` πετά έξω τα `NULL`.

**Τα αθροίσματα είναι φουσκωμένα;**
Αθροίζεις στήλη του «ενός» πίνακα μετά από `JOIN` με τον «πολλά». Υπολόγισε το άθροισμα σε
χωριστό CTE στο σωστό επίπεδο και μετά ένωσε.

**Λείπουν γραμμές που «ξέρεις» ότι υπάρχουν;**
Ψάξε `NULL`. Είναι σχεδόν πάντα τα `NULL`.

Ένα γρήγορο τεστ λογικής: πάρε **έναν** πελάτη και επαλήθευσε τον αριθμό με το χέρι.

```sql
SELECT o.id, o.order_date, b.title, i.quantity, i.unit_price,
       i.quantity * i.unit_price AS γραμμή
FROM orders o
JOIN order_items i ON i.order_id = o.id
JOIN books b ON b.id = i.book_id
WHERE o.customer_id = 1 AND o.status = 'paid'
ORDER BY o.order_date;
```

---

## 10.4 Καλές συνήθειες

- **Ονόμασε τα πάντα.** `AS τζίρος` αντί για `SUM(i.quantity * i.unit_price)` στο αποτέλεσμα.
- **Ψευδώνυμα πινάκων παντού** σε ερωτήματα με `JOIN` — και προθεμάτισε κάθε στήλη (`o.id`,
  όχι σκέτο `id`). Όταν δύο πίνακες έχουν στήλη `id`, το ασαφές `id` είναι σφάλμα.
- **Ένα CTE ανά βήμα σκέψης**, με όνομα που λέει τι κάνει.
- **`LIMIT` όσο πειραματίζεσαι** σε μεγάλους πίνακες.
- **Σχόλια για το «γιατί»**, όχι για το «τι». Το `-- μόνο πληρωμένες, οι ακυρωμένες δεν
  μετράνε στον τζίρο` αξίζει· το `-- επιλέγει τίτλο` όχι.

## 10.5 Τι μαθαίνεις μετά

- **`EXPLAIN` και βελτιστοποίηση** — να διαβάζεις πλάνα εκτέλεσης
- **Διαφορές διαλέκτων** — PostgreSQL, MySQL, SQL Server, Oracle. Το 90% είναι κοινό·
  διαφέρουν οι συναρτήσεις ημερομηνίας/κειμένου και οι επεκτάσεις
- **Τύποι JSON** και ημιδομημένα δεδομένα
- **Επίπεδα απομόνωσης** συναλλαγών και ταυτοχρονισμός
- **Ασφάλεια:** SQL injection — **ποτέ** μην χτίζεις ερώτημα με συνένωση κειμένου από είσοδο
  χρήστη· χρησιμοποίησε παραμετροποιημένα ερωτήματα (`WHERE id = ?`)

Και το βασικότερο: **ρώτα τη δική σου βάση**. Πάρε δεδομένα που σε ενδιαφέρουν πραγματικά
και προσπάθησε να απαντήσεις ερωτήσεις που θέλεις όντως να ξέρεις. Μαθαίνεται μόνο έτσι.
