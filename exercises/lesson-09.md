# Ασκήσεις — Μάθημα 9 (Σχεδιασμός, περιορισμοί, ευρετήρια)

Λύσεις: [`solutions/lesson-09.sql`](solutions/lesson-09.sql)

> Και εδώ αλλάζει η βάση. Επαναφορά: `python3 tools/build_db.py`

1. Φτιάξε πίνακα `publishers` με: `id` πρωτεύον κλειδί, `name` υποχρεωτικό και μοναδικό,
   `city`, και `founded` που να δέχεται μόνο έτη μετά το 1400.

2. Πρόσθεσε στον `books` στήλη `publisher_id` που αναφέρεται στον `publishers`.
   *Σημείωση:* η SQLite δεν επιτρέπει προσθήκη στήλης με `REFERENCES` και `NOT NULL`
   ταυτόχρονα — άσε τη στήλη προαιρετική.

3. Καταχώρισε 2–3 εκδότες και σύνδεσε μερικά βιβλία με αυτούς.

4. Δοκίμασε να παραβιάσεις τους κανόνες και δες τι μηνύματα παίρνεις:
   - βιβλίο με αρνητική τιμή
   - παραγγελία με `status = 'άκυρο'`
   - παραγγελία για πελάτη που δεν υπάρχει
   - δεύτερος εκδότης με το ίδιο όνομα

5. Φτιάξε ευρετήριο στο `orders(customer_id)`. Πριν και μετά, τρέξε:
   ```sql
   EXPLAIN QUERY PLAN SELECT * FROM orders WHERE customer_id = 5;
   ```
   Τι αλλάζει στο πλάνο;

6. Φτιάξε **μοναδικό** ευρετήριο που εμποδίζει τον ίδιο πελάτη να γράψει δύο κριτικές για
   το ίδιο βιβλίο. Μετά δοκίμασε να εισαγάγεις διπλή κριτική.

7. Φτιάξε όψη `v_πωλήσεις_βιβλίων` με τίτλο, τεμάχια και έσοδα ανά βιβλίο (και τα αδιάθετα
   με 0). Χρησιμοποίησέ τη σε ερώτημα.

8. **Σχεδιασμός:** θέλουμε «λίστα επιθυμιών» — κάθε πελάτης μπορεί να σημειώσει πολλά
   βιβλία, και κάθε βιβλίο μπορεί να είναι στη λίστα πολλών πελατών. Τι πίνακα/πίνακες
   χρειάζεσαι; Γράψε το `CREATE TABLE`.

9. **Κριτική σχεδιασμού:** τι είναι λάθος στον παρακάτω πίνακα και πώς θα τον έσπαγες;

   ```sql
   CREATE TABLE παραγγελίες_κακό (
       id           INTEGER PRIMARY KEY,
       πελάτης      TEXT,      -- 'Μαρία Παπαδοπούλου'
       email        TEXT,
       πόλη         TEXT,
       βιβλία       TEXT,      -- '1984, Ζορμπάς, Ποιήματα'
       συνολικό_ποσό REAL
   );
   ```

10. **Σκέψου:** γιατί ο πίνακας `order_items` κρατά `unit_price`, ενώ η τιμή υπάρχει ήδη
    στον `books.price`; Δεν είναι περιττή επανάληψη;
